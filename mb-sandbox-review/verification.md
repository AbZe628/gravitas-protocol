## Isolation and security scope

The changed Solidity files are isolated reference contracts under `mb-sandbox-review/reference/`. The existing `contracts/GravitasPolicyRegistry.sol`, production-facing contracts, root tests, deployment configuration and root `foundry.toml` were not modified. The only Foundry permission change is inside the isolated reference project: it explicitly permits importing the unchanged sibling registry source. The GitHub workflow change collects the generated local evidence as a build artifact.

The reference package implements a fixed-manager gated token and a holder-initiated manager transfer. It refuses direct and delegated transfer routes, prevents a third party from redirecting a holder's manager allowance, checks registry asset and executor/pause rules, and emits token and manager transfer events atomically. The API is read-only; its separate consumer-client helper fails closed and does not sign or submit transactions. An API ALLOW and later transfer are not atomic.

## What the checks do not prove

This is not an independent audit, security certification or production integration. The demo token is not a real financial asset and has no legal or religious standing. Asset approval and executor authorization do not establish investor identity, KYC/AML, sanctions status, accreditation, suitability or recipient eligibility. `checkSubscriptionCompliance` accepts a subscriber argument but does not independently inspect it. Caller-supplied amount, channel and request ID are not authoritative compliance evidence. No verified identity/eligibility provider, ruling workflow, hosted API, key custody, mainnet deployment or production pause/exit policy is implemented.
