# Sample audit record

`sample-audit-record.json` combines values returned by the registry, policy-change and ERC-20 events, and JSON-RPC block and receipt responses. Its outer keys are a review fixture, not an on-chain event or stored audit schema.

The token event records a transfer of 100 GUSD units from Anvil account 0 to account 2. With 18 decimals, the event value is `100000000000000000000`. The token is `contracts/MockERC20.sol`, not a sukuk.

The registry check calls `checkSubscriptionCompliance(subscriber, subscriptionToken)` at block `0x4`. Its ABI result decodes to policy version `3`. The contract checks the asset flag and `isExecutor[msg.sender]`; it ignores `subscriber`. Version 3 followed the constructor executor grant at version 1, the asset addition at version 2, and the second executor grant at version 3. `PolicyUpdated` carries version and change hash, not the ruling text or identifier.

The separate GUSD `Transfer` occurred at block `0x5`. The check and transfer were not one transaction. GUSD did not call the registry. The record therefore shows a successful check followed by a separate transfer; it cannot prove that the transfer enforced version 3. The production section explains the one-transaction record to build.

The fixture is generated by `scripts/check-local.py`. A new local run will have different transaction hashes and timestamps. All addresses and amounts are local dummy values.
