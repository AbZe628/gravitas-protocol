# The full audit

Started **9 September 2026**. Every finding here is a counted fact with a file
and a line, or a number measured against the running application. Where a count
could not be reproduced, it says so instead of repeating it.

**Scope reached so far: the Majlis client and the Majlis server.** The protocol,
the SDK, the integration kit, the public site, `apps/web` and the other
repositories are listed in §7 as not yet audited. Nothing in this file describes
them.

---

## 0. How the numbers were produced

Two servers were run from a clean build, both seeded, on ports the owner's own
instance does not use:

```
apps/majlis/client   npm run build -w client     (rebuilt: the server serves client/dist)
port 4100            no credentials              every session is an observer
port 4101            MAJLIS_MEMBERS set          all eight roles, generated locally
```

The credentials were generated by `npm run members -w server` into the session
scratchpad. Nothing was written to a tracked file, and they are throwaway.

Screens were measured in a headless browser driven over CDP, which — unlike the
in-app browser — carries HTTP basic authentication, so each role was opened as
that role rather than inferred from `curl`. Widths 375 and 1440. The scripts are
in the session scratchpad, not in the repository.

**Three counters were wrong before they were right, and were fixed rather than
reported.** They are written up in §6, because each is a trap the next session
would otherwise fall into as well.

## 1. The first screen, and the thing the owner keeps saying

### F1. The arrival screen contradicts itself, and only on the instance every visitor sees

`client/src/pages/Guided.tsx:166`

```
A question has waited 56 days.
Nothing is waiting for you today.
```

The two sentences sit one under the other, the first in the page's largest type.

`Pressing` picks the board's most pressing fact and renders it. The line beneath
it, `guided.clearShort`, is printed **unconditionally** — it is outside the
branch, so it appears whether or not anything is pressing.

The comment above the component says the two sentences are deliberately
different — one is about the board, one about the reader — and that reasoning is
sound. The implementation does not carry it: nothing tells the reader which
sentence is about whom.

Measured per role at 375px:

| role | headline | line beneath | contradiction |
|---|---|---|---|
| observer | *A question has waited 56 days.* | *Nothing is waiting for you today.* | **yes** |
| chair (`member-a`) | *READY TO TAKE EFFECT — overdue by 32 days* | (attention list is not empty) | no |
| bank desk | *Put a question to the board* | — | no |

The demonstration instance runs with no credentials, so **every person shown
this application is the observer**, and the observer is the one case that
contradicts itself.

### F2. `/classic` opens with 450 words before the board's work

`/classic` is the **main** destination of door 02, *Deciding* —
`client/src/lib/spine.ts:96`. It is what the *Deciding* tab opens.

Measured at 375×812, signed in as an observer:

| | |
|---|---|
| words on the page | 631 |
| first link to an actual record | y = **1682px**, i.e. **2.07 screens down** |
| page height | 4.1 screens |

What comes first, in order: a 44-word notice that this session cannot take part;
*What this is* (30 words); four explanatory blocks (~250 words); *What it will
never do* (three paragraphs, ~90 words) and an *I have read this* button. Then
the board's work.

At 1440px the first record link is at y = 995 — still below the fold.

### F3. The same contradiction as F1, again, on `/classic`

On the same page, in this order:

```
Nothing is waiting for you.
The board decides in 12 days
waiting now 2
range 8-82 days
```

*Nothing is waiting for you* sits directly above *waiting now 2*.

## 2. Navigation and reachability

### F4. Ten of seventeen destinations are absent from the phone's navigation

`lib/spine.ts` defines 17 destinations (14 under the four doors, 3 in
`BESIDES`). Read from the rendered DOM:

| width | destinations reachable from the navigation on any screen |
|---|---|
| 1440 | 17 — `/ /questions /ask /classic /meetings /undertakings /calendar /rules /register /library /check /calculations /briefings /examinations /incidents /settings /search` |
| 375 | **7** — `/ /search /settings /questions /classic /rules /examinations` |

At 375px the tab bar carries only each door's `main` screen. The other ten are
listed on the arrival screen and nowhere else, so on a phone **every one of them
costs a return to home first**. There is no back-to-parent affordance inside a
door.

This is the same complaint as the eleven-screens-behind-a-hidden-rail finding,
in a new shape: the rail was replaced by tabs, and the tabs carry four of the
fourteen door destinations.

### F5. Six server routes no screen ever calls

107 routes are mounted across 11 route files. Cross-referenced against every
`/api/...` string the client builds, with the path templates normalised on both
sides — and the matcher proved on four hand-checked cases first (§6):

| route | file:line | what is unreachable |
|---|---|---|
| `POST /committees/:id/dissolve` | `routes/committees.ts:219` | a committee can be formed and never dissolved |
| `POST /referrals/:id/withdraw` | `routes/committees.ts:330` | a referral cannot be withdrawn |
| `GET /computations/:id` | `routes/computations.ts:116` | one saved calculation cannot be reopened |
| `POST /matters/:id/sources/:sourceId/against` | `routes/governance.ts:764` | evidence cited *against* a position cannot be recorded |
| `GET /rules/:id/review` | `routes/governance.ts:1209` | one rule's review |
| `GET /disclosure` | `routes/incidents.ts:349` | the year's non-compliance disclosure |

`GET /disclosure` is the costly one. It already returns exactly what an annual
Shariah report needs — the event, its reference, the amount to be purified, its
destination, whether it was paid, the four rectification steps, and the total
outstanding by currency — and no screen in the product opens it.

### F6. Two addresses render one page; the page named after the decisions is not in the navigation

`client/src/App.tsx` routes both `/rules` and `/record` to `WhatStands`. Measured
at 375px the two are identical in every respect (190 words, 4 links, 5 controls,
first record link at y=430).

`Record.tsx` — the screen actually titled *What we decided* — is mounted only at
`/classic/record`, which appears in no navigation at any width and in
`spine.ts` not at all.

### F16. The demonstration record hides the entire meeting lifecycle

The seed contains **one meeting**, `meeting-2026-08-20`, and its state is
`closed`. `pages/Meetings.tsx:240` renders the minute field and
`pages/Meetings.tsx:167` the attendance control only while
`row.state !== 'closed'`.

So on the record every visitor is shown, the secretary — the one role a
supervisor names as keeper of the minute — sees this on `/meetings`:

```
controls: ["Show the record"]
fields:   0
```

Convening one meeting through `POST /api/meetings` changes it to:

```
controls: ["Hide the record","Record attendance","Save the minute","Show the record"]
fields:   8
```

**The feature is complete and reachable. The demonstration data hides it.**
Minute-taking, attendance and closing a sitting are the three capabilities every
board portal is bought for, and no one shown Majlis has ever seen them.

The fix is in the seed, not the code: the record needs one meeting already held
and minuted, and one convened and still open.

## 4. The bank's own desk

This matters more than the rest, because the deliverable is something a bank
can be sent.

### F7. The desk's arrival screen has no way out of itself

Signed in as `desk-treasury` (role `institution`), at 375px, `/` renders the
*Put a question to the board* form, then *What I asked* with the desk's own
question and a *Withdraw this* control. 148 words, 7 controls, and **0 links**.

The form and the record of its own questions are good, and are the right two
things. But the desk's only navigation is the board's four doors, which take it
to the board's screens: the queue, the deliberation, the rules, the
examinations. There is no destination shaped for the institution — what was
ruled that binds me, what I owe the board, what I must do next.

### F8. The refusals are correct, and worth keeping

Probed as `desk-treasury` against `matter-2026-08-11`:

```
POST /api/matters/:id/vote    403  role_not_permitted
  "This credential may not vote. This credential belongs to the institution
   rather than to the board. It puts questions to the board and reads what
   became of its own..."
```

A stated sentence, the right status code, no 500. This is the standard the rest
of the product should be held to, and it is met here.

### F15. The interface offers the bank's desk eight controls the server refuses

This is the worst one, because it is in front of the bank on the first screen a
bank would click, and because it breaks the product's own rule that **a control
that cannot be honoured is absent, not disabled**.

Opened as `desk-treasury` at 1440px, `/matters/matter-2026-08-11` offers:

| control | count | server's answer |
|---|---|---|
| *Record a finding* | 6 | `403 role_not_permitted` |
| *Reply* / *Add to the deliberation* | 2 | `403 role_not_permitted` |

```
POST /api/matters/:id/deliberation   403  "This credential may not deliberate..."
POST /api/matters/:id/findings       403  "This credential may not record a finding..."
```

The refusals themselves are exactly right — a stated reason, the right code.
The fault is that the buttons are drawn at all. The institution presses *Record
a finding* on the board's matter and is told it is not allowed to.

The same controls were probed as `advisory` and `liaison`: both return `400`
for a malformed payload rather than `403`, so both **are** permitted and the
controls are correctly offered to them. **The defect is specific to the
`institution` role**, which is the one role a bank sees.

## 5. Language, documents, and the seam

### F9. The dictionaries are in exact parity — the numbers in STATE.md are stale

Counted by importing the module the application itself loads, not by reading the
file (see §6):

| | |
|---|---|
| keys, each language | **1213** en / 1213 ar / 1213 ur |
| present in one language and not another | **0** |
| empty values | **0** |
| Arabic identical to English | 3 — `late.dayCount.360`, `late.dayCount.365`, `terms.keyHint` |
| Urdu identical to English | the same 3 |
| English strings over 25 words | **74** |
| English strings containing an em dash | 16 |

STATE.md's *1196 keys* is stale but its parity claim is true. Its *55 strings
over 25 words* is now 74.

### F10. Nine different failures say the same nine words

`"That did not go through."` is the text of nine keys: `cttee.failed`,
`margin.failed`, `raise.failed`, `und.failed`, `found.failed`, `tell.failed`,
`read.failed`, `acct.failed`, `sign.failed`.

A member whose vote failed and a member whose margin note failed read an
identical sentence, and neither is told what failed or what to do.

68 English sentences are shared by two or more keys (141 pairs). Most are
genuinely different contexts — *of*, *waiting*, *Currency* — exactly as STATE.md
says. Two are one object under two names:

- `"Withdrawn"` is `reg.status.retired` as well as `matter.status.withdrawn`.
- `"Lapsed"` is `attention.overdueKind` as well as `matter.status.lapsed`.

**The 87 pairs in STATE.md could not be reproduced.** The measure here is 68
groups / 141 pairs, counted from the loaded dictionary.

### F11. `unnamed-fields` does not exist

STATE.md §0 item 4 says *twenty-nine fields have a visible label with no
`htmlFor`* and instructs the next session to `run unnamed-fields against src`.

There is no file matching `*unnamed*` anywhere in the repository.

Measured instead, two ways:

- **In the rendered DOM**, across 25 screens as the chair at 1440px: 18 fields
  render on arrival, and **6 have no accessible name — all of them on `/ask`**.
  This undercounts, because fields inside panels a person must open first are
  not rendered until they open them.
- **In the source**: 93 `<input|select|textarea>`, 68 `<label>`, and only
  **5 `htmlFor`** and 30 `aria-label`. Most labels must therefore be wrapping
  their field, which is valid.

The number 29 is neither confirmed nor refuted; what is certain is that the tool
named in the handoff cannot be run.

### F12. There is no PDF engine

`grep` across `server/src` and `server/package.json` for `pdfkit`, `puppeteer`,
`playwright`, `PDFDocument`, `application/pdf`: **one hit**, and it is a MIME
type in `store/vault.ts:68` for files coming *in*.

`services/fatwa.ts` renders HTML for a browser to print. Every document the
board produces — the fatwa, the board book, the annual report, the audit export,
a holding's record, a matter's pack — leaves as HTML or JSON. Stage D2's "out"
half is entirely unbuilt, which the code says plainly and the documentation
should too.

### F13. Six font families load from Google at runtime

`client/index.html:8,9,25` preconnects to `fonts.googleapis.com` and
`fonts.gstatic.com` and pulls Manrope, Newsreader, IBM Plex Mono, Amiri, Noto
Sans Arabic and Noto Nastaliq Urdu.

A bank on a filtered network sees fallback faces, and the Arabic and Urdu faces
are the ones that matter most. Every page load also tells Google that someone
opened it.

### F14. The seam: the default is `none`, and the shipped example overrides it

`services/enforcement.ts:87-104` is right. Unset means `NoEnforcement`, and the
comment says an installation with nothing attached is complete rather than
degraded.

But `.env.example:163` ships `POLICY_REGISTRY_ADDRESS=0x6f3b...` **uncommented**,
and `enforcementFromEnv` infers `gravitas-registry` from its presence. Both
servers started for this audit reported `"enforcement":"gravitas-registry"`
without anyone choosing it. `docs/DEMO.md:35` hands a bank the same line.

So a bank following the documentation gets a chain read it did not ask for,
against a testnet, and the honest `none` path — the one the design is proudest
of — is the path nobody takes.

**The addresses themselves are clean.** `0x6f3bfb896DD9964C9c05dA88692bDf1b1b2C3F23`
is the current registry per `docs/DEPLOYMENTS.md:17`. The superseded
`0xbcaE3069...` and `0x5D423f8d...` appear only in `DEPLOYMENTS.md:45-46` and
`CHANGELOG.md:22,78`, both correctly labelled as superseded. Nothing hands out a
stale address.

## 6. Three counters that were wrong first

Recorded because each would otherwise be repeated.

**The route matcher.** A naive comparison of the server's `/matters/:id/vote`
against the client's `` `/api/matters/${id}/vote` `` reports a false
unreachable — this is the error that produced "36 unreachable routes" in an
earlier audit when the true number was 3. Both sides are now normalised to
`matters/*/vote`, and the matcher is proved against four hand-checked cases
before it prints anything. It also under-counted the routes themselves at first
(23 instead of 107) because the path often sits on a line after `router.get(`;
the fixed count agrees with `grep` file by file.

**The dictionary counter.** Three wrong answers in a row. The block boundaries
cannot be inferred from repeated keys; the file mixes `'single'` and `"double"`
quoting, so a parser that sees one style reports 348 parity gaps that do not
exist; and long values wrap over several lines, so counting lines that look like
keys over-counts. The only reliable count is to `import` the module the
application loads.

**A text corruption that was mine, three times over.** Page text kept coming
back with the letter *s* replaced by a space — `conditions` as `condition`,
`This session reads` as `Thi  e ion read `. It looks exactly like a font or
rendering fault in the application. It is not.

The cause is an escape eaten at every level between the audit script and the
browser. A probe containing `.replace(/\s+/g, ' ')` reaches the page as
`/s+/g` and replaces runs of the letter *s*. It survives being blamed on the
console, on the heredoc, and on the template literal in turn, because **each of
those really does eat one backslash**: a quoted bash heredoc on this machine
collapses `\\s` to `\s`, and a JavaScript template literal collapses `\s` to
`s`.

Proved by evaluating two expressions in the page and comparing:

```
"this session reads conditions"                     -> this session reads conditions
"this session reads conditions".replace(/\s+/g,' ') -> thi   e ion read  condition
```

The fix that holds: **the page returns raw text and Node tidies it**, so no
backslash ever crosses the boundary. Scripts written with the Write tool rather
than a heredoc were never affected, which is why the measurements in §1 to §5
stand — they were all written that way.

**Nothing that looked like a text corruption bug in Majlis was real.**

## 7. Not yet audited

Named so the gap is not mistaken for a clean bill:

- `contracts/` — the Solidity, the governance contracts, the Foundry tests and
  scripts, what is deployed where.
- `gravitas-sdk/` against the contracts it wraps.
- `integration-kit/` — OpenAPI, mock server, policies, scenarios.
- `site/`, `_pages/`, `apps/web` — every page and every claim on it.
- The other repositories: `gravitas-protocol-frontend`, `Index`.
- Majlis screens in Arabic and Urdu at each width. Only English was measured.
- The roles `liaison`, `advisory`, `secretary` and the plain `signatory` were
  authenticated and swept, but their journeys have not been walked end to end.
- Every refusal path on all 107 routes. Three were probed by hand.
