04 / HUMAN GOVERNANCE
Majlis records governance activity; it does not submit Registry updates.
Phase 1 audit ↗

      

        
IMPLEMENTED · APPLICATION
What the code can demonstrate
Authenticated matter/proposal routes, reasoning and vote records, role checks, a signatory quorum calculation, lifecycle progression, objections, expiry and application-level timelock handling, canonical parameter hashing and sealed decision records.
Relevant evidence: Majlis server governance/lifecycle/signature services and focused tests. Test data is seeded demonstration data.

        
NOT IMPLEMENTED · ON-CHAIN HANDOFF
What it cannot claim
A completed Majlis vote does not create a verified Ethereum signature that submits policy parameters to the deployed Registry. A parameter hash is not an approval signature. The “in force” application status is not proof of on-chain enactment.
No real institutional members, votes, mandates or board records are represented here.

05 / EXECUTION CONTRACTS
Two bounded DeFi operations, not a payment network.
V2 on Arbiscan ↗

      

        
TELEPORT V2
V2-style liquidity migration
Burns caller-provided LP tokens, then adds the resulting same pair through an authorized V2-compatible router; checks Registry executor/router/assets; enforces a cooldown and max LP-share movement; returns defined dust.
No cross-chain messaging, bridge, swap path or deployed V2 DEX route on Arbitrum Sepolia was established in the audit.

        
TELEPORT V3
Signed NFT position migration
Uses an EIP-712 intent with chain/contract domain separation, owner/signature verification, nonce and deadline, removes and collects a V3 position, optionally performs a bounded single-hop rebalance, then mints a new position and refunds defined excess.
Tests cover modified fields, wrong signer, replay and expiry. Dedicated wrong-chain-ID and wrong-verifying-contract negative cases remain NOT EXECUTED. Local tests use deterministic mocks; not a live Uniswap fork.

08 / LIMITATIONS
Evaluation boundaries matter.

      

        
01
No KYC or eligibility. Registry address/token/router/executor flags are allow-lists, not identity verification, AML screening, sanctions controls or investor qualification.

        
02
No Azerbaijan legal entity. No local eligibility or sandbox application is claimed; the third-cycle application period has passed.

        
03
Not an audit. This is an internal technical review. No independent security audit or security certification is claimed.

        
04
Timelock ownership gap. The deployed Registry's observed owner is a separate EOA, not the deployed Timelock; Registry pending owner read as zero.

        
05
Atomicity is bounded. A revert rolls back a single EVM transaction; it does not eliminate market, oracle, liquidity, governance, smart-contract, legal risk or all gharar.
